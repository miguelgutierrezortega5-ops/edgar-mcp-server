# Trading bot research

The bot lives in `trading-bot/` (TypeScript, `npm test` offline). Read `trading-bot/README.md` for usage.

## Method (keep it, it is what makes results trustworthy)

1. **Measure before building.** Turn an idea into a detector and run an event study: mean forward return after the event, at several horizons, from the *next* bar's open, against the all-bars baseline and the round-trip cost (~0.3% on Binance spot with slippage).
2. **Check look-ahead bias** with `npm run verificar` after changing a strategy.
3. **Split time.** Discover on the older part, validate on the newer part. Report only what holds in both, in most markets, and above costs.
4. **Simulate real trades** (stop, target, time stop, fees) before trusting an event study: averages can hide paths that hit the stop first.
5. **Count independent episodes, not trades.** Crypto events cluster (one crash day fires a dozen coins). Group by day.
6. **Never tune on the data you report.** The learner (`src/learn.ts`) does walk-forward; say plainly when a result is in-sample.

Data: `data-api.binance.vision/api/v3/klines` (public, global, includes taker-buy volume) via `src/data/binance.ts`. Futures positioning via `src/data/futures.ts`: `data.binance.vision` daily `metrics` zips (5-min open interest, top-trader and global long/short ratios, taker ratio; complete days up to yesterday, reachable from US containers) and monthly `fundingRate`; `fapi.binance.com` fills the current day but is geo-blocked from US containers (works from Mexico). Liquidation snapshots are no longer in the archive.

Before telling the user to install or update anything, test a fresh clone from GitHub (`git clone --branch ... && npm install && npm test`): a too-broad `.gitignore` once kept `src/data/` out of the repo while the working copy built fine. The user runs the bot on an Android phone (Termux, `scripts/android/`), so it must build with pure-JavaScript TypeScript 5 and keep data usage low (candle cache in `data/velas`). Phone UX: the user types on a phone keyboard, so everything goes through the `bot` shortcut (`scripts/android/bot.sh`) and guided helpers (`bot telegram`) instead of paths or file editing; scripts run via `curl | bash` must wrap their body in a function and keep stdin away from child commands. Updates reach the phone as commits on the branch: the bot announces pending commit subjects on Telegram and `/actualizar` installs them, so write every commit subject in plain Spanish describing what changed for the user (they read it on the phone). A version that fails to build is undone by `applyUpdate`; one that crashes twice right after starting is undone by the supervisor (marker files `.actualizacion-*`). Automatic installation (`updates.auto`, hourly, simulated accounts only) is on in `config.reto50.json` since 2026-10-02 at the user's explicit request (the permission system had blocked enabling it without that). So every push to the branch reaches the phone within the hour and restarts the bot: push only tested work (tests + fresh clone), and batch notes-only changes with real ones. The phone pins a daily JSON report in the Telegram chat (authorized by the user); read it with `TELEGRAM_BOT_TOKEN=$(cat <scratchpad>/telegram.token) TELEGRAM_CHAT_ID=$(cat <scratchpad>/telegram.chat) node scripts/leer-informe.mjs <file>` from trading-bot/ — never print or commit the token.

Token-efficient workflow: put research scripts in the scratchpad, cache klines to disk, print one compact table per run, and reuse `npm run estudiar` / `npm run aprender` instead of ad-hoc dumps.

## Findings so far (Binance spot, 16 pairs of $1-8M/day, 3m bars, May-Oct 2026)

- Capitulation (-3% in 10 bars on 4x volume) bounces **only when BTC falls too** (liquidation cascade): PF 1.7-3.3 in both halves. Isolated flushes (BTC calm) lose: real selling.
- Pumps (+3% / 10 bars, 4x volume) revert -0.4% to -0.7%. Highs swept and closed back below: negative. Breakouts with aggressive buying: no follow-through.
- Wide stops (1.5 ATR under the flush low) work; 0.5 ATR stops get hunted.
- EMA crossover loses on BTC/ETH 1h; forex needed slower settings (20/100, stop 3 ATR).
- Always judge with the portfolio simulator (`simulate`, one shared account, `maxOpenPositions`): per-market backtests overstated capitulation (PF 2.17 → 1.36 shared). Protections (cooldown 20 bars, 3 stop-losses in 60 min → 4 h pause) brought it to PF 1.88, max drawdown 2.4%, +7.7% in 150 days.
- Keep losing strategies out of a shared account: they take the position slots and trip the drawdown halt. Crypto and forex now have separate paper accounts.

- Microstructure algorithms (src/quant.ts), measured May-Oct 2026: VPIN, Kyle's lambda, Amihud alone have no stable edge (they track each period's drift). As context for capitulation: high VPIN helped and high Amihud hurt in both halves, but with 9-35 cases. Hurst's relation to capitulation flipped sign between halves: do not use it as a filter.
- The adaptive layer (decayed evidence per strategy x context, half-life 30 days) did not raise returns over a period where the edge held (+7.26% vs +7.65%); with a 10-day half-life it cost 3 points. Treat it as insurance, and re-measure it when the edge fades.
- Deflated Sharpe of the learner's best combination: 0.42 (capitulation, 216 trials) and 0.08 (forex EMA, 108 trials): grid winners were mostly luck.
- The user insists that nothing in this market is a law: present every finding as "measured in period X", keep re-measuring, and prefer mechanisms that adapt over hard-coded filters.
- The user (2026-10-03) wants alternatives searched actively whenever results stagnate. Stagnant (window set by the user to 2 days, because crypto flows change fast) = over the last 2 days a challenge made <= +0.2%, or a side sat in "solo observa" for 2+ days, or challenge 2 traded far less than the replay of the same days says it could. Two days of trades is a small sample, so the trigger means "investigate now"; the switch still has to beat the current rule on longer out-of-sample data. For challenge 1 (agreed with the user 2026-10-04) the 2-day check is only "the phone took every signal the replay shows"; its P&L is judged per 30 days (<= 0 over 30 days triggers the search), because its gains come in bursts (<= +0.2% in 83% of 2-day, 64% of 14-day and 57% of 21-day windows over 150 days that made +8.35%). Then research alternatives (ideas list below, other coin selections, leaders thresholds, exits, other strategies) with the same method: walk-forward, holdout months, costs; switch only to what beats the current rule out of sample, and tell the user what changed and why.

- Futures (150 days, 15 pairs): open interest +3% in 30 min was followed by -0.2% to -0.6% over 4 h in both halves (baseline -0.09%/+0.12%), confirmed again on the last 60 days. Other futures readings track the baseline. Capitulation split by open-interest change flips between halves: not a filter.
- Adaptive sizing by context (toxicity, liquidity, futures), even judged one dimension at a time, did worse than the group-only evidence (PF 1.67 vs 1.82; none 1.85): `useContexts` is off by default.

- Challenge 1 comes in bursts: 150-day replay to 2026-10-04, 129 trades on only 35 days (+8.35%, PF 1.78, 145 more signals skipped by the 8-position cap and protections); 58% of 2-day windows had no entry and 83% made <= +0.2%. The 2-day stagnation trigger is therefore almost always on for it and says little: for challenge 1, check over 2 days that the phone took every signal the replay shows, and judge its P&L over weeks.
- $50 challenge (150 days + 10,000-path day-block bootstrap): more risk per trade or fewer, larger positions made results worse (2%/50%: -3%; 5%/100%: -11%); the best was diversified (1% risk, 12.5% per position, 8 positions: +8.0%, drawdown 2%). P(50 -> 250 within a year) was 0% at every level. Do not promise growth targets; size small and spread out.
- Paper/backtests now enforce Binance's 5 USD minimum order and spot cash (no leverage): needed for small accounts.

- Challenge 2, wick hunter (`src/mechas`, 1-minute futures candles Jun-Sep 2026, scratch data in the session only): classic grids (paired buy/sell ladders, neutral/long/short) lose after fees or flip sign between periods; buy-only grids only ride the drift of rising coins. Orders near the price (1.5-2 σ15) win 60-79% of the time and still lose: a >50% hit rate is not an edge, the mean after costs is. Resting buys at 4·σ15 below the last close (target back to it, stop one distance, 30 min) beat random entries with identical exits (+0.66%/+0.48% vs -0.17%/-0.14%) on the study coins, but were ~0% on 14 unseen coins: coin selection drove it. Walk-forward (rank by previous month's median daily range, trade next month, 94 established perps): top 12 + leaders calm gave buys +0.35/+0.80/+0.91% and shorts +0.56/+0.42/+0.18% (Jul/Aug/Sep); picking coins by last month's strategy P&L did not persist. Wicks while BTC falls >0.3% in the same minute lose (-1.71% Aug-Sep): the opposite of the 30-min capitulation finding, where only cascades bounce. The filter can only use data known before the minute (leaders' previous 5 min > -0.2%). 1-minute OHLC simulation undercounts grid round trips when steps are tighter than the 1-minute range (random-walk control comes out negative), so only wide steps are trustworthy. Selling at the minute close when price already passed the target (bot-realistic exits) did not lower results. The bot replays September with that month's coins at 71% wins, +0.91% per buy, matching the study; its learner paused shorts by month end.
- Spot-only hosts (US) pick calmer coins for challenge 2 (spot volumes) and trade far less: judge it from the phone's report, not from a cloud run.
- Challenge 2 holdout, Mar-May 2026 (never used for any choice; coins walk-forward from the previous month's 1d futures archive): the edge is much weaker. Full bot: buys +0.12%/trade (60% wins), shorts -0.01%, account 50.77 (+1.5% in 3 months, drawdown -6.7%); without the learner 50.56 with drawdown -11.1%. Jul-Sep with the same bot: 66.79. Expect something in between: flat in calm months.
- Exit variants: the hindsight best of 192 on Jul-Sep (stop 2x, 60 min: 93.34 vs 72.58) was worse on the holdout (44.98 vs 49.19). Month-to-month rank correlation of variants 0.13-0.39. Online "trade the best recent variant" was as often worse as better; a strict switch (>= 60 days, z >= 3 on the daily P&L difference, decayed 30 d) never fired in 6 months, so the bot ships that (shadow variants, `src/mechas/shadow.ts`) as harmless insurance. With few days z comes out high by chance (7-day replay showed z 3.0): never trust a short window.
- Learner rule: pausing on doubt (P(mean>0) < 0.6, half-life 14) paused buys right before their best stretches in both periods (observed-but-skipped buys +1.59% Jul-Sep). Pausing on evidence of losses (< 0.3, half-life 30) kept most of the upside and still paused the losing holdout shorts. Prior now 0.3% / 60% wins (Mar-Sep average).
- Second holdout, Dec 2025-Feb 2026 (coins walk-forward from the previous month's 1d archive, same 94-coin universe): the full bot **lost**, 47.58 (-4.8% in 3 months, every month negative, drawdown -5.4%); real buys -0.12%/trade at 66% wins (too little evidence to pause them), shorts -1.05% on 18 trades and then paused. So: Jun-Sep +33.6% (in-sample), Mar-May +1.5%, Dec-Feb -4.8%. The edge is regime-dependent; do not expect the Jun-Sep pace. Months where the chosen coins' average median daily range was 23-27% (Jul-Sep) were all strongly positive and those at 12-16% mostly negative, but the strong months are also the in-sample ones (parameters chosen there), and out of sample alone (Dec-May) there is no clear link: not usable as a filter yet. Live Oct coins average 21.6%.
- Learner grid on all three periods (minProbability 0.3/0.4/0.5 x half-life 30/14, prior 3 trades): the current rule (0.3, 30 d) had the best total (+15.1 USD over the three 3-month runs; others +10.7 to +14.8); none rescued Dec-Feb (all 46.4-48.0). Keep it.
- Per-coin momentum before the fill (the coin's own 5/15/60-min move in units of the order distance): scanning Jun-Sep and Mar-May suggested skipping shorts after a 15-min drop > 0.5 distance (-4.16% n13, -0.76% n14); on the fresh Dec-Feb holdout that bucket was +1.86% (n8). Noise from scanning 36 cells: rejected. Fill-minute stops (exit at the close when the entry candle closes past the stop: the stop is not resting yet) are 3-6% of trades and a large share of the losses in every period (Jun-Sep longs -80% summed vs +149% total).
- Research data for these studies lives only in the session scratchpad (h2/ Dec-Feb, sets2.json, diag.mjs = real bot with per-trade features; m1/ Jun-Sep, h1/ Mar-May, 1-minute Float32 columns); the bot can replay any period with `node dist/index.js mechas --monedas ... --dias N --hasta YYYY-MM-DD` (archive cached in data/<config>/velas1m).

- Order lifetime while the phone sleeps (`orderMinutes`, real bot, Markov sleep 30% of minutes in 8-minute blocks, seeded): 1 min (current) 60.79 / 51.11 / 46.37 (Jun-Sep / Mar-May / Dec-Feb; awake 66.79 / 50.77 / 47.58); 5 min 65.11 / 47.92 / 45.34; 10 min 78.40 / 46.45 / 47.64; 15 min 75.57 / 46.81 / 47.01. Stale resting orders fill more: better in-sample, worse in Mar-May, flat in Dec-Feb: not adopted (default 1). Kept: a tick that runs > 15 s late now places its orders for the following minute (before, a phone always late placed none) and orders already resting in the current minute stay for it.
- Coin's own 24 h range before a fill (2026-10-07, diag with r24; cut points chosen on Jun-Sep terciles 11.5% / 23.3%): shorts on calm coins (r24 < 11.5%) lost in all three periods per trade (-0.55% n56, -0.22% n102, -0.32% n69), longs showed no stable pattern. As a real-bot filter (shorts only when the last 24 full hours ranged >= X): none 66.79 / 50.77 / 47.58 (Jun-Sep / Mar-May / Dec-Feb), 8% 67.65 / 48.98 / 48.25, 11.5% 68.78 / 51.05 / 47.37, 15% 68.09 / 49.46 / 48.42. The gain sits in-sample and the learner already pauses losing shorts: not adopted (code reverted, not shipped).
- Longs only (`shorts: false`, real bot, same three periods; maxPositions 6 changed nothing): Jun-Sep 59.14 (DD -5.2%) vs 66.79 with shorts, Mar-May **52.82** (DD -4.2%) vs 50.77, Dec-Feb **48.90** (DD -4.8%) vs 47.58. Adopted in config.reto50.json on 2026-10-08 (the live short side had been observe-only for 5 days, mean -0.78%). Revisit if a long Jun-Sep-like stretch returns: the shorts' evidence was in-sample only.
- What higher-return bots do differently (web review 2026-10-04, user asked): (1) **trend following on 6 h-daily bars** with low win rates and big winners (top Hyperliquid vaults win 28-48% of trades; AdaptiveTrend arXiv 2602.11708 claims Sharpe 2.41 OOS 2022-24 with monthly re-optimization, -4% in bear years; Zarattini/Pagani/Barbon 2025 "Catching Crypto Trends": Donchian ensemble 5-360 d, trailing stop at the channel midpoint, 25% vol target, Sharpe > 1.5 on the top 20); our challenges are the opposite payoff (high win rate, capped target, full stop: the BTW -13.8% is that tail). (2) **Structural premia that need scale**: market making/liquidations (HLP ~15-30% APR, drawdowns 5-12%) and funding carry (Ethena sUSDe 4-30%, mostly 8-18% in 2024-25, depegged to 0.65 in Oct 2025). (3) **Bull beta, leverage and survivorship**: grid/DCA "15-40%" are bull-market holding; median bot user ~9-11%/yr; ~70% of copy traders report liquidations; leaderboards select winners.
